## Discrepancies and lead decisions

- CLAHE's small-crop clamp is an existing compatibility choice recorded in C1 log 24-25. A literal `tile x tile` effective grid conflicts with that choice when a crop side is undersized. The helper's square-grid description also conflicts with its axis-by-axis implementation on rectangular crops. The backfill can leave the accommodation unspecified while preserving the requested grid. If the lead wants a binding exception to the historical grid wording or to change the implementation, decide that separately from this append-only backfill.
- Static numerical risk in `pipeline.py:316-318`. `Preset` accepts a finite Python float such as `1e40` for `blue_gain` (`types.py:27-44,116-118`). Float32 conversion can turn it into infinity and yield invalid arithmetic for zero blue. Rounding/clipping can still saturate positive blue under default floating-point handling, but the cast/multiply can warn or fail under stricter NumPy error settings. The declared computation on zero is exactly zero. Keep the output guarantees and treat this as an implementation edge to verify separately. Existing gain tests cover 1.0, 1.3 and 1.5, so they cannot resolve it. Likewise, `math.isfinite` can overflow converting huge Python ints that pass the type check (`types.py:41-44`), leaking `OverflowError` instead of the specified invalid-field `ValueError` if such values are rejected. These are static findings, with no runtime reproduction performed.
- `types.py:40` overgeneralizes NumPy float subclassing. The check uses actual `int`/`float` inheritance and C1 log 25 explicitly says NumPy `float32` is rejected. Preserve the scalar corner as open and treat the comment as a source documentation discrepancy, outside this edit scope.
